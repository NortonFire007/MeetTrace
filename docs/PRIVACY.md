# MeetTrace Privacy & Security Architecture

MeetTrace is built from the ground up on **local-first** and **privacy-first** principles. This document outlines the architectural boundaries and guarantees enforced by the application.

---

## 1. Core Principles

1. **Local-First Audio Processing:** 100% of audio capture and speech-to-text transcription occurs locally on your Windows machine. Raw audio is never sent to any cloud server, third-party service, or remote API.
2. **No Meeting Bots:** Unlike cloud recording bots (e.g. Otter, Read.ai) that join calls as external participants, MeetTrace records natively from your Windows Core Audio subsystem (WASAPI loopback + microphone). No bot joins your meeting.
3. **Strictly Sandboxed Browser Extension:** The companion Chrome extension has zero access to web audio, video streams, or microphone devices.
4. **No Telemetry or Tracking:** MeetTrace does not include analytics, tracking beacons, error tracking SDKs, or cloud telemetry.
5. **Durable Ownership:** All transcripts and meeting notes belong entirely to you and are stored in standard human-readable formats (Markdown and JSON) on your local hard drive.

---

## 2. Audio Processing Lifecycle

```text
[Microphone] ──(WASAPI)──┐
                         ├──> [AudioCaptureService] ──> [faster-whisper (Local Engine)]
[Speakers]   ──(WASAPI)──┘                                     │
                                                               ▼
                                                     [Local Storage Archive]
                                                     %USERPROFILE%\MeetTrace\meetings\
                                                        ├── transcript.json
                                                        └── meeting.md
```

- Audio chunks are processed in temporary in-memory buffers.
- Once transcription segments are derived, the raw PCM audio buffers are discarded from RAM and are not persisted to disk, conserving disk space and ensuring confidential conversations cannot be leaked as audio files.

---

## 3. Chrome Extension Security Boundary

The Chrome extension uses Google Chrome Manifest V3 with the minimal possible privileges:

```json
{
  "manifest_version": 3,
  "name": "MeetTrace Bridge",
  "permissions": ["storage"],
  "host_permissions": [
    "https://meet.google.com/*",
    "http://127.0.0.1/*"
  ]
}
```

### Enforced Limits:
- **Zero Media Permissions:** The extension does **NOT** request `tabCapture`, `audioCapture`, `desktopCapture`, `activeTab`, or `webRequest`. It is physically impossible for the extension to capture or access audio or video from your calls.
- **Localhost-Only Communication:** Communication is restricted strictly to `http://127.0.0.1:38281/api/v1/meetings/events`. No remote servers are contacted by the extension.
- **Cryptographic Token Authentication:** All requests from the extension must present an authentic Bearer token generated by the desktop application. Unauthenticated requests are rejected with HTTP 401.

---

## 4. Optional Cloud Summarization (Gemini)

If and only if you explicitly choose to configure a Gemini API key:
- **Post-Meeting Only:** Summarization only runs when you click "Generate Summary" on a completed meeting.
- **Transcript Text Only:** Only the extracted text of the transcript is transmitted over HTTPS to the Google Gemini API endpoint. Raw audio is never transmitted.
- **No Cloud Storage by MeetTrace:** MeetTrace operates without intermediate backend servers; requests go directly from your local machine to the official Google Gemini API endpoint.
- **Air-Gapped / Offline Operation:** If no Gemini API key is provided, MeetTrace operates completely offline without making any outbound network connections.

---

## 5. Secret Protection & Local Logging

- **Secret Redaction:** MeetTrace automatically filters all log output written to `%USERPROFILE%/.meettrace/logs/meettrace.log` using regex masking filters. Bearer tokens and Gemini API keys are redacted before touching disk or console.
- **Local Settings:** Configuration and API keys are stored locally in the Windows Registry under `HKEY_CURRENT_USER\Software\MeetTrace\MeetTrace` using standard Windows user permissions.
